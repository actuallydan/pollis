# Mobile OTA updates (#1250)

The mobile app replaces its own JS bundle + assets over the air, signed, from our
own Expo Updates server. Runbook and key handling: `mobile/CLAUDE.md` → "OTA updates".
Deploy facts: `docs/deployments.md` → "6. Mobile OTA updates" / "Update server".

## Pieces

| Piece | Where | Notes |
|---|---|---|
| App config | `mobile/app.config.js` (`updatesConfigFor`) | On only for `POLLIS_OTA=production`; then URL, `ON_LOAD`, `fallbackToCacheTimeout: 0`, channel header, `codeSigningCertificate` + `codeSigningMetadata {keyid: main, alg: rsa-v1_5-sha256}`. Otherwise `{enabled: false}`, no URL. |
| Runtime version | `app.json` `runtimeVersion.policy: fingerprint` + `mobile/fingerprint.config.js` | Local `@expo/fingerprint`, no EAS. Adds pollis-core + its path-dep crates, Cargo files, toolchain, ubrn version, the OTA certificate; ignores ubrn output, version fields, the `updates` block. |
| Certificate | `mobile/store/ota-code-signing.pem` | Public half only; generated by `mobile/scripts/generate-ota-signing-key.sh` (owner). |
| Pipeline | `mobile/scripts/ota-publish.ts` + `mobile/scripts/ota/lib.ts` | `build` → `sign` (only step with the key) → `upload --phase content` → `attest` → `log-append` → `upload --phase live` → `verify`; `prepare-republish` / `prepare-rollback` for rollbacks. `lib.ts` imports only `node:` built-ins. |
| Workflow | `.github/workflows/mobile-ota-release.yml` | `mobile-ota-*` tags / dispatch; `sign` job in the `ota-signing` environment (required reviewer). |
| Server | `pollis-updates/worker/protocol.ts` (Worker `pollis-updates`, R2 `pollis-updates`) | Protocol v1 `GET /api/manifest` + `GET /assets/<sha256>`; passes pre-signed bytes through; no key, no logs. |
| Transparency | binaries tree, tag `mobile-ota-<group>` | `ota-manifest` / `ota-bundle` / `ota-assets` / `ota-directive` leaves, `arch` = runtime version. |

## R2 layout (`pollis-updates`)

```
current/production/<platform>/<runtimeVersion>.json   live pointer {kind, body, signature}
assets/<sha256>                                        content-addressed bundle/asset bytes
updates/<updateId>.json                                archive (republish source)
groups/<groupId>.json                                  one publish/republish/rollback
```

## Tests

- `mobile/tests/ota-manifest.test.ts` — manifest shape, sign/verify (incl. against
  Expo's own signer), store-build checks, transparency leaves vs `binaries.rs`.
- `mobile/tests/ota-worker.test.ts` — sign → Worker → client verification end to end.
- `mobile/tests/ota-config.test.ts` — dev builds can't take prod updates, prod builds
  are code-signed, fingerprint coverage, the signing job's environment.
- `pollis-updates/tests/*.test.ts` — protocol responses; Workers Logs/Logpush off.
- `verifiable-log-serve/tests/binaries_e2e.rs` — OTA groups verify alongside desktop releases.

All signing in tests uses a throwaway certificate generated in memory per run.
